这个文件是什么

aoe2de_techs.xs 是一份 AoE2DE 的 XS 脚本（.xs）。脚本在决定版的场景与 AI 脚本里被当作嵌入式语言使用，用于读取科技、单位、玩家状态等游戏数据。

整份文件只有一件事：399 条 extern const int 定义，构成「科技常量名 → techID」的一一映射，不含任何逻辑、函数或条件分支。

extern 表示这些常量是外部可引用的：任何 #include 或加载了本文件的 XS 脚本，都能直接用常量名取到对应的 techID，不必在代码里硬编码数字。const int 则表明它们在脚本生命周期内是只读的。

常量名遵循 TECH_ + 英文科技名的命名规则，非法字符会被替换。最典型的是撇号：Northmen's Fury 的常量名是 TECH_NORTHMEN_S_FURY，而不是 TECH_NORTHMEN'S_FURY。

使用陷阱：退役常量会静默失败

源文件头部注释里最需要记住的一条：在 XS 里引用已退役的科技常量，既不报错，也不产生任何效果。

不抛异常、不返回错误码、不中断脚本。调用效果等同「未研究」——这是彻底的静默失败。因此绝不能用「常量在文件里存在」去推断「这个科技当前可用」。需要判断可用性，必须自己查文明科技树。

已知局限

以下事项来自源文件头部注释，都是明确列出的，不是推测。

主动剔除：Elite Qizilbash Warrior 未收录。 它的 techID 只有「DAT 内部名启发式对齐」这一条证据支撑：AI 常量表里没有 qizilbash / 967，62 个文明科技树对 Qizilbash 命中 0，unitlines.json 的 IDChain [1817, 1829] 给的是单位 ID 而非科技 ID，文本索引 N=449 与 967 之间也没有可推导的关系。无法验证的 ID 会导致脚本静默研究错科技，因此整条不收录（见脚本的 REVERSE_DENY）。这是「宁缺勿错」的取舍。

同名冲突保留传统文明名称。 同一个 techID 被传统文明（era=base）与 Chronicles 新文明（era=antiquity）复用时，保留传统文明的名称，因为其编号经锚点验证为真实 DAT techID。冲突明细在导出脚本的 stdout 里。

DAT 对齐是启发式的，不是完整解析。 empires2_x2_p1.dat 是压缩容器（raw deflate，解压后约 89.0 MiB），脚本按 0x600A 记录标记 + 名称匹配率来定位科技表，科技表名称匹配率 57%。因此 DAT 只用于给退役科技定位 techID，不作为全量枚举来源；匹配率越低，退役条目的 techID 越需要人工复核。

退役 techID 若被新内容复用，常量名会与真实语义不符。 本文件按名称文本保留，无法从文本侧发现这种 ID 复用。

部分单位升级科技的描述缺失。 少数单位升级科技在中文文本表里没有「升级到 X」条目，注释只有名称、没有描述。本文表格中这类条目的效果描述列填 —。本文件里只有一条：TECH_CHAMPI_SCOUT（蔷琵斥候，1350）。
